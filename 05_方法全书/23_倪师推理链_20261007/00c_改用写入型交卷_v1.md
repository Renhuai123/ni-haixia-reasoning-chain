# 补记：后续子代理改用写入型交卷（2026-10-07）

## 改了什么

只改交卷方式，不改任何整理规则。

- **原来（回复型）**：子代理只读材料，最终回复是一份 JSON。
- **现在（写入型）**：子代理用写入工具，把同样格式的 JSON 写进派活提示指定的那一个文件，最终回复只写「已写入」。
- 子代理类型：从 opus-high-reader（只能读）换成 opus-high-writer（能读、能写）。两者都是 Opus 5.5、推理档位 high。

## 为什么

回复型的完整结果会原样回传到主对话里。35 批抽取、35 批裁定、35 批核查、6 组归一加起来有一百多份，会占满主对话的上下文。写入型只回传「已写入」三个字。

## 哪些用哪种

| 环节 | 交卷方式 | 说明文件 |
|---|---|---|
| 抽取 K01–K09（第一波，已派出） | 回复型 | chain_extract_instructions_v2.txt（材料包 chain_packets_v2） |
| 抽取 K10–K35 | 写入型 | chain_extract_instructions_v2w.txt（材料包 chain_packets_v2w） |
| 试裁定 K06、K10（已派出） | 回复型 | chain_adjudicate_instructions_v1.txt |
| 正式裁定、核查、归一 | 写入型 | 对应的 *_v1w.txt |

各 w 版说明与原版逐字相同，只有「纪律」里两行不同：

- 「不写文件」改为「只用写入工具把结果写进派活提示里指定的那一个文件，不写别的文件」；
- 「最终回复只输出一份 JSON」改为「写进文件的是一份 JSON……写完后最终回复只写『已写入』」。

## 审计（save_chain_returns_v2.py）

两种交卷方式由子任务记录自动判断：记录里有写入调用的算写入型。写入型的审计：

- 工具调用只许读本批文件夹，加上写入指定的那一个交卷文件；
- 每个材料文件每一行都要读到；
- 交卷文件能解析，且与记录里最后一次写入调用的内容完全相同。

## 裁定材料包

裁定材料包里的 extract_instructions.txt 一律取 chain_packets_v2 里的回复型说明。这份文件只用来让裁定者看清整理规则；两版的整理规则逐字相同。各批的 batch.json、context.txt 在 v2 与 v2w 两套材料包里逐字节相同，建包时按 SHA-256 核对。
