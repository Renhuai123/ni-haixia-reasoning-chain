# 倪海厦紫微斗数断法推理链：数据与代码

[![DOI](https://zenodo.org/badge/1409903367.svg)](https://doi.org/10.5281/zenodo.23232530)

这是论文《从讲述到推理链：倪海厦紫微斗数断法的逐步推理引擎》（于仁坪，2026）的数据、代码、AI 答卷与登记文件。论文只以倪海厦《天纪》讲稿为规则来源，把他「由盘面直接下判断」的起步与「后一个判断由前一个判断推出」的推理步逐条抽出来，做成推理链知识库（1685 步、1028 个判断结点，每一步附原话）和第四版引擎，并报告事先登记的各项检验。

- 论文正文（第十八稿，投稿版）：[`05_方法全书/22_倪师断法论文_20261007/定稿_推理链_v18_投稿版/正文/`](05_方法全书/22_倪师断法论文_20261007/定稿_推理链_v18_投稿版/正文/)（PDF 与 Word）
- 补充材料：[`…/定稿_推理链_v18_投稿版/补充材料/`](05_方法全书/22_倪师断法论文_20261007/定稿_推理链_v18_投稿版/补充材料/)（PDF、Word，以及 T 编号与视频分集、时间点的对照表）
- 存档与 DOI（Zenodo）：<https://doi.org/10.5281/zenodo.23232530>（所有版本；v1.0 为 <https://doi.org/10.5281/zenodo.23232531>，2026-10-08 存档，含论文 PDF）

本研究只问引擎像不像倪海厦，不问紫微斗数准不准；不主张紫微斗数有预测效力。

## 怎么核

只用 Python 3 标准库（重画插图另需 matplotlib）。

```bash
python3 verify_manifest.py
```

逐个重算 7386 个文件的 SHA-256，与 `MANIFEST.tsv` 和登记表摘录对照。

```bash
cd 05_方法全书/22_倪师断法论文_20261007
python3 check_chain_paper_v13.py --paper 论文正文_v18.md --supp 补充材料_v18.md --out /tmp/check.json
```

重跑论文的核数：从结果文件、答卷、程序源码算出论文里每个数字应有的写法（507 项），逐项到正文和补充材料里找；另核 39 条原话引文、附录样例与图表编号。应与 `checks/chain_check_v13_paper_v18.json` 相同（全部合格，未覆盖 0 句）。

```bash
cd 05_方法全书/23_倪师推理链_20261007
python3 chain_coverage_v1.py --kb chain_kb_v1.json --charts v4_holdout_v1/holdout_charts.json --out /tmp/coverage.json
```

用 600 张留出随机盘重跑第四版引擎的覆盖统计，应与 `chain_results_v1/coverage_v1.json` 相同。上面两项都在整理本仓库时实际跑过，结果一致。

## 登记

方案、说明、脚本与中间结果在运行之前登记 SHA-256，之后不改；改动另出新版本并写明理由。登记由作者本机自存，没有第三方时间戳：公开只能证明这些指纹最晚在公开时已经存在，不能独立证明登记的先后。

`02_实验/preregistration_hashes.json` 是完整登记表的摘录：只留下含本仓库文件的登记条目（121 条），每条的时间、理由和该次登记的全部文件指纹照原样抄录。完整登记表共 3409 条，另含本研究以外其他课题的文件路径，没有公开。

`MANIFEST.tsv` 最后一列是每个文件与登记的对照：

| 对照 | 文件数 | 说明 |
|---|---|---|
| 与登记一致 | 5115 | 指纹与该路径最近一次登记相同 |
| 已脱敏（原文件与登记一致） | 14 | 原文件与登记相同；公开前把本机目录与用户名换成了占位符，所以现在的指纹不同（原指纹、新指纹见 `SANITIZED.json`） |
| 同一内容在别的路径下登记过 | 1262 | 多为各批材料包里相同的说明文件与语料 |
| 指纹写在已登记的文件里 | 612 | 多为材料包与答卷，指纹记在已登记的清单或审计文件里 |
| 未登记 | 382 | 主要是答卷的审计摘要（由已登记的完整对话记录生成，对话记录不公开，见下）、API 批次回执与原始返回、排版中间文件 |
| 登记表摘录 | 1 | 即 `02_实验/preregistration_hashes.json` |

## 没有公开的

- **命主的出生资料，以及据此排出的命盘。** 论文里命主只用编号。主检验（`chain_reproduce_v1.py`）和两次认本人的出题脚本要用到这些资料，所以这几步不能在本仓库里从头重跑；它们的结果、全部答卷与审计摘要都在。
- **子代理的完整对话记录**（`*.transcript.jsonl`，311 份）：里面夹带作者本机与本研究无关的个人设置。每份答卷本身和据此生成的审计摘要（`*.audit.json`）都在。
- **网站排盘引擎快照。** 排盘器 `chart_runner_v1.cjs` 调用的是 Metis 正式站 2026-10-01 的只读快照，不在本仓库。开源版排盘引擎见 <https://github.com/Renhuai123/ziwei-doushu>（与该快照是否逐位相同，没有核对过）。本仓库直接提供排好的随机盘。
- **前作（未刊稿）的稿子与其余实验材料。**
- **完整登记表**（见上）。

另有 16 个文本文件把本机目录与用户名换成了 `<第三篇根目录>`、`<用户名>` 一类占位符，逐个列在 `SANITIZED.json`。

## AI 使用

推理链的抽取、裁定、逐步核查与归一，第一次认本人检验的审者、旧的推理类型归类、召回率的找漏与裁定，都由 Anthropic 的 Claude Opus 5.5 的独立实例完成。第二次认本人检验的审者、用 Fable 重审第一次认本人的审者、传统框架的切分与归类，以及三轮论文内审，是经 Claude API 批量接口逐个独立调用的 Claude Fable 5.1。程序编写、统计、核数与论文写作也由 Claude 完成。上游的转写语料由 xAI 的 Grok 整理、Claude 核验。作者提出问题，提供资料与经费，确定目标与范围，审阅分析与文字，对全部内容负责。没有人类专家复核：每一步都挂着原话与 T 编号，读者可以逐条对照倪海厦的讲课视频（B 站 BV1KJsLekEfA）核对。
